# 운영 전 통합 검증 절차

아래 절차는 실제 운영 Firebase를 사용하지 않는다. `firebaseEmulator=1`은
`localhost`와 `127.0.0.1`에서만 동작하므로 운영 URL에 붙여도 무시된다.

## 자동 검사

```sh
npm ci
npm run check
npm run test:emulator
```

- `check`: 멱등 요청, 지연 후 재시도, 잘못된 데이터 방어, 5,000건
  페이지네이션, 오래된 응답 무시, TV 리스너 중복 방지 및 JavaScript 문법을
  검사한다.
- `test:emulator`: 운영 데이터와 분리된 `demo-nchm`에서 Rules 문법,
  동일 requestId, 일일 참여 키, 동시 슬롯, 관리자/일반 사용자 권한,
  잘못된 쓰기를 검사한다.

## 브라우저 수동 검사 준비

터미널 1:

```sh
npx firebase emulators:start --only auth,database --project demo-nchm
```

터미널 2:

```sh
python3 -m http.server 8000
```

브라우저에서 다음 주소를 연다.

```text
http://127.0.0.1:8000/index.html?firebaseEmulator=1
```

DevTools의 Network 탭에서 Offline/Slow 3G를 사용할 수 있다. 검사가 끝나면
두 서버를 종료한다. 에뮬레이터 데이터는 운영 프로젝트로 전송되지 않는다.

## 사용자 등록과 장애 복구

1. 최초 접속 후 로딩 화면이 사라지고 방문/AR 입력 카드가 각각 한 번만
   만들어지는지 확인한다.
2. 이름, 나이, 목적을 입력하고 저장 버튼을 빠르게 5회 누른다. 버튼은
   `저장 중...`으로 비활성화되고 로그는 인원 수만큼 한 번만 생성되어야 한다.
3. Slow 3G에서 저장을 누른 직후 새로고침한다. 15분 이내 재접속 시
   `중단되었던 저장 요청` 완료 메시지가 나타나고 동일 requestId 로그는
   늘어나지 않아야 한다.
4. 같은 URL을 두 탭에 열고 동일 입력을 거의 동시에 저장한다. 두 탭이 공유한
   pending requestId는 최종 한 건만 남아야 한다.
5. Offline에서 저장한 뒤 Online으로 복귀한다. 오류가 표시되더라도 입력 화면은
   계속 조작 가능해야 하며, 재시도 시 기존 pending requestId를 사용해야 한다.
6. AR에서 두 탭이 같은 시간 슬롯을 동시에 누른다. 한쪽만 성공하고 다른 쪽은
   `같은 시간을 먼저 예약` 안내를 보여야 한다.

## 날짜 변경과 절전 복귀

1. 브라우저/OS 테스트 시간을 23:59로 맞춘 뒤 방문 및 AR 화면을 연다.
2. 자정이 지난 뒤 표시 날짜와 AR 예약 구독이 새 날짜로 한 번만 바뀌는지
   확인한다.
3. 노트북을 자정 전 절전 상태로 두고 자정 후 복귀한다. 탭이 다시 보이는 즉시
   날짜, 시간 슬롯, 이벤트 상태가 갱신되어야 한다.
4. DevTools에서 `getEventListeners(window)`와 Performance 패널을 사용해
   날짜가 바뀔 때마다 같은 Firebase value listener나 분 단위 타이머가
   추가되지 않는지 확인한다.

## 관리자와 대용량 조회

1. Auth Emulator에 관리자 이메일 계정을 만든 뒤 로그인한다. 잘못된 비밀번호,
   네트워크 차단, 올바른 비밀번호를 차례로 시험한다.
2. `전체`, `월별`, `지정 기간`을 빠르게 바꾼다. 가장 마지막 조건의 결과만
   보여야 하고 이전 응답이 화면을 되돌리면 안 된다.
3. 각 페이지는 최대 100건이어야 한다. 이전/다음 이동에 중복 또는 누락이
   없어야 하며, 통계·CSV가 현재 페이지 기준이라는 안내와 건수가 일치해야 한다.
4. Network 탭에서 읽기 요청 하나를 차단한 뒤 `조회`를 다시 누른다. 무한 로딩
   없이 오류 안내 후 재시도가 성공해야 한다.
5. Emulator에 잘못된 기존 레코드(null 사용자, 잘못된 배열 등)를 Rules 비활성
   테스트 컨텍스트로 섞어 넣는다. 해당 행만 안전하게 건너뛰고 나머지 통계와
   목록이 표시되어야 한다.

## TV 장시간 검사

1. TV 페이지를 2시간 이상 열어 두고 탭 숨김/복귀와 네트워크 단절/복구를
   반복한다.
2. Firebase `value` 리스너는 각 활성 데이터 소스당 하나, 날짜 확인 타이머는
   하나만 유지되어야 한다.
3. 날짜가 바뀌면 오늘 방문/AR 구독이 새 날짜로 교체되고 이전 쿼리는 `off`
   되어야 한다.
4. 이벤트 기간 로그는 최대 5,000건만 메모리에 있어야 한다. 초과한 관리자
   순위 카드에는 최근 5,000건 기준 안내가 표시되어야 한다.

## 모바일/데스크톱

Chrome DevTools에서 390×844와 1440×900을 각각 확인한다. 입력 카드, 필터,
이전/다음 버튼이 가로로 잘리거나 겹치지 않아야 하며 방문·AR·관리자 탭
전환 후에도 저장 버튼과 목록을 사용할 수 있어야 한다.
